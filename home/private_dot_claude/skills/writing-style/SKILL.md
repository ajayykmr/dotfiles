## Message drafts

For a Slack, Teams or email message:

- If the current project has a `drafts/` folder at its root, write the draft to a file there named `<YYYY-MM-DD>-<recipient-or-channel>-<topic>.md`, and give me the path. Otherwise, give the message in your reply, ready to paste, without creating a file.
- The file holds only the message, ready to paste. Questions, assumptions and open points go in your reply, not the file.
- Revise the same file until the message is sent; start a new file only for a new message.
- Re-read the file before every revision, since I may have edited it. Build on my edits; never overwrite or revert them.
- Revise with targeted edits unless I ask for a rewrite, and say briefly what changed.

PR descriptions, commit messages and documents are written where they belong, not in `drafts/`. For PR structure, follow the `pr` skill if it's installed; this style sets the voice.
